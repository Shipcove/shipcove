Quick start

Run the platform on a machine with Docker, from the images published on the GitHub registry, in about ten minutes.

Prerequisites

  • Linux (or macOS with Docker Desktop) with Docker 24+ and Docker Compose v2;
  • git and openssl;
  • at least 4 cores, 8 GB of RAM and 30 GB of disk (more depending on the number of simultaneous sandboxes: 2 CPUs / 4 GB each by default);
  • an API key from a model provider (Anthropic, OpenAI…) — or the mock provider for a first try.

Installation

  1. Get the deployment files

    The repository contains the Compose file, the bootstrap scripts and the LiteLLM configuration; the applications themselves are downloaded as images.

    git clone https://github.com/Shipcove/shipcove.git
cd shipcove/infrastructure/docker

  2. Configure

    cp .env.example .env

    In .env, set at least:

    # Images published on ghcr.io
CAP_REGISTRY=ghcr.io/shipcove/
CAP_VERSION=0.1.0
CAP_SANDBOX_IMAGE=ghcr.io/shipcove/shipcove-sandbox:0.1.0

# Initial administrator (created on first start if none exists)
CAP_ADMIN_EMAIL=admin@example.com
CAP_ADMIN_PASSWORD=a-long-and-unique-password

# Group owning the host Docker socket (value given by: stat -c %g /var/run/docker.sock)
CAP_DOCKER_GID=989

    Replace 0.1.0 with the latest published version: every vX.Y.Z tag of the repository publishes the X.Y.Z images (see the Packages of the GitHub repository). All the images of an installation must have the same version.

  3. Generate the bootstrap secrets

    ./scripts/init-secrets.sh

    The script creates .secrets/ (PostgreSQL passwords, Garage and LiteLLM keys, Vault AppRole credentials). It is idempotent: run again, it replaces nothing. This directory is never committed; protect it and back it up.

  4. Pull the images and start

    docker compose pull
docker pull ghcr.io/shipcove/shipcove-sandbox:0.1.0
docker compose up -d

    On first start, Vault is initialized and unsealed, S3 storage (Garage) is configured and the database migrations are applied. Check the status:

    docker compose ps
curl -s http://localhost:8080/api/v1/health/ready

  5. First login

    Open http://localhost:8080 and sign in with CAP_ADMIN_EMAIL / CAP_ADMIN_PASSWORD. Administrators must enable two-factor authentication (TOTP) at their first login: scan the QR code with your authenticator app and keep the recovery codes.

  6. Connect LiteLLM and enable a model

    Models are declared in LiteLLM (its interface at http://localhost:4000/ui with the master key from .secrets/litellm_master_key, its API or its config.yaml); the platform discovers them.

    • Administration → Models (LiteLLM), LiteLLM connection card: keep the bundled LiteLLM, or enter the URL and admin key of an existing LiteLLM proxy (Test, then Save);
    • Reload models: the LiteLLM models appear, disabled, with coefficients prefilled from their known prices (1 credit = $0.001);
    • enable one, make it the default, then Test sends a real request. A user allowlist can restrict access to a model (empty = everyone).

  7. Invite users and start a conversation

    • Administration → Invitations: invite your colleagues by email (requires an SMTP server: Administration → Notifications & SMTP), or create their accounts in Users;
    • on the home page, write your first request to the agent; optionally pick a repository under the input box (after configuring a Git forge and connecting your account).

Try without a model provider

The dev profile adds a mock LLM provider (scriptable, for acceptance testing) and Mailpit, which captures emails:

docker compose --profile dev up -d

Then declare the openai/mock-model model with the api_base parameter set to http://mock-llm:4010/v1 and any key. Emails can be seen at http://localhost:8025 (configure the SMTP server mailpit:1025 in the administration).

The dev profile is not meant for production.

Upgrade

# in .env: CAP_VERSION and CAP_SANDBOX_IMAGE to the new version
git pull
docker compose pull
docker pull ghcr.io/shipcove/shipcove-sandbox:<version>
docker compose up -d

Migrations are applied automatically by the migrate service before the APIs start. Running sandboxes keep their image until their next restart.

What next?

  • Installation and configuration: public URL, TLS, previews, ports, replicas;
  • Identity and SSO to connect your directory;
  • Git forges to work on your repositories;
  • Operations before going to production.
