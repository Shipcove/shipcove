Contributing

pnpm monorepo in TypeScript 6 (ESM): Angular 22, NestJS 12, Drizzle, Zod 4, Vitest.

Layout

FolderContent

Getting started

pnpm install
pnpm dev:infra          # PostgreSQL, Vault, Garage, LiteLLM, Mailpit, mock LLM
pnpm build
pnpm typecheck && pnpm lint

Prerequisites: Node.js 26, pnpm 12.18, Docker.

Database

pnpm db:generate        # new migration after a schema change

Migrations are versioned in packages/database/migrations and applied by the migrate service at startup.

Tests

pnpm test:infra:up              # PostgreSQL, Vault, S3 for integration tests
pnpm test                       # unit and integration tests (Vitest)
cd tests/e2e && pnpm test       # end-to-end on the Compose stack (dev profile)

The end-to-end suite covers the interface (Playwright), the functional flows, Git against a real GitLab, SSO against Keycloak and OpenLDAP, and resilience (loss of an API, of the worker, S3, LiteLLM, Vault failures). Optional providers, in tests/e2e: pnpm sso:up (Keycloak, OpenLDAP), pnpm forge:up (GitLab CE); without them, the related suites are skipped.

Images

pnpm images:build                                   # local images cap-*:0.1.0
CAP_REGISTRY=ghcr.io/shipcove/ CAP_VERSION=0.2.0 pnpm images:build

The CI only builds and publishes the images when a version tag is created (vX.Y.Z, checked before the build):

git tag -a v0.3.0 -m "Shipcove 0.3.0"
git push origin v0.3.0

Documentation

pnpm docs:dev                       # http://localhost:5174
pnpm docs:build                     # static site in apps/docs-site/dist
DOCS_BASE=/docs/ pnpm docs:build    # publishing in a subfolder

The site is bilingual: each page exists in apps/docs-site/fr/ and apps/docs-site/en/, under the same name; add it to the navigation (titles in both languages) in vite.config.js. Internal links are written relative (guide.html). The root page picks the language from the browser (English by default) and remembers the choice made with the selector. The dist folder can be published as is on any static hosting.

Project rules

  • Dependencies: only versions published more than two weeks ago are accepted (minimumReleaseAge); install scripts are refused by default.
  • Contracts: every API input is validated by a schema from @cap/contracts.
  • Secrets: never in the repository, the logs or the API responses.
  • Decisions: a structural change comes with an ADR.
  • License: the code is under the AGPL v3; a contribution is published under that license.
