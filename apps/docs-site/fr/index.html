Shipcove

Build in a safe cove. Ship with confidence.

Une plateforme auto-hébergeable où vos équipes confient des tâches de développement à un agent de code. Il lit, modifie et teste le code dans une sandbox éphémère et isolée, pousse ses branches et ouvre ses pull requests en autonomie ; chaque modification est sauvegardée, et ce qui est irréversible (branche principale, fusion, suppression) est approuvé par un humain.

Démarrage rapide →Lancer la plateforme en quelques minutes à partir des images publiées. Guide utilisateur →Conversations, dépôts, Git, plan, previews. Administration →Modèles, quotas, identité, forges Git, sandboxes et services. Sécurité →Isolation des sandboxes, secrets, approbations, confidentialité.

Ce que fait la plateforme

  • Un workspace par tâche : depuis un dépôt GitHub / GitLab (SaaS ou auto-hébergé) ou vierge, avec sa conversation, ses fichiers et sa sandbox.
  • Un agent autonome : il exécute des commandes, écrit du code, lance les tests, démarre au besoin une base PostgreSQL ou un Redis, et vous montre chaque action.
  • Rien ne se perd : un checkpoint est publié sur S3 après chaque écriture ; une sandbox détruite est restaurée à l’identique, et vous pouvez revenir à l’état d’avant n’importe quel message.
  • Il montre son travail : un plan de tâches tenu à jour pour les demandes complexes, des captures d’écran prises d’office dès qu’une interface web change, un git diff à jour, et ses livrables (README, rapport, export…) proposés au téléchargement.
  • Rien d’irréversible sans vous : l’agent pousse ses branches et ouvre ses pull requests seul, mais la branche par défaut, les fusions et les suppressions de branche attendent votre approbation, directement dans la conversation.
  • Vos modèles, vos règles : tous les appels passent par LiteLLM (Anthropic, OpenAI, Azure, Bedrock, Mistral, modèles locaux…), avec quotas personnels.
  • Prête pour l’entreprise : SSO (OIDC/Keycloak, SAML, LDAP/AD, GitHub, GitLab), MFA, secrets dans Vault, audit, rétention des données.

Comment ça marche

  1. Vous écrivez une demande dans une conversation, liée ou non à un dépôt Git.
  2. La plateforme démarre (ou réutilise) la sandbox de la conversation, restaure ses fichiers et l’état de l’agent.
  3. L’agent travaille : pour une tâche complexe, il établit d’abord un plan ; chaque appel d’outil (commande, lecture, écriture) s’affiche en direct ; chaque écriture déclenche un checkpoint.
  4. Vous suivez les fichiers modifiés dans l’onglet Git (git diff, branche de travail), testez l’application via une preview, et approuvez dans la conversation la publication Git proposée par l’agent.
  5. Après une période d’inactivité, la sandbox est détruite ; tout est conservé sur S3 et repart au message suivant.
