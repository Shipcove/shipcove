Forges Git

Les utilisateurs rattachent leurs comptes GitHub / GitLab par OAuth, via les forges déclarées par l’administrateur. Les jetons restent dans Vault et n’entrent jamais dans les sandboxes.

Déclarer une forge

Administration → Forges Git, une application OAuth par forge :

ForgeOù créer l’application
GitHub.comSettings → Developer settings → OAuth Apps → New OAuth App
GitHub Enterprise ServerMême chemin, sur votre instance
GitLab.comParamètres → Applications (application confidentielle)
GitLab auto-hébergéAdmin Area → Applications → New application (confidentielle)

  1. Ajouter

    Type, nom affiché, hôte (fixe pour les offres SaaS), Client ID, secret client (Vault).

  2. Déclarer chez la forge

    L’URL de rappel affichée par la console (https://<votre-domaine>/api/v1/me/git-connections/oauth/<id>/callback) et les portées : GitHub repo read:user user:email read:org, GitLab api read_user read_repository write_repository.

  3. Tester

    La console vérifie que la forge répond et que l’identifiant et le secret client sont acceptés.

  4. Activer

    La forge apparaît dans Paramètres → Connexions Git des utilisateurs.

Supprimer une forge révoque les connexions qui en dépendent. Les jetons d’accès personnels sont désactivés par défaut (réglage Autoriser les jetons d’accès personnels).

Côté utilisateur

  • Connecter via … : autorisation sur la forge (PKCE, état à usage unique), retour automatique.
  • Les jetons qui expirent (GitLab : 2 h) sont renouvelés automatiquement ; une connexion expirée côté forge affiche Reconnecter.
  • Un projet se crée ensuite à partir d’un dépôt accessible avec la connexion choisie.

Lecture et publication

  • Lecture : la sandbox clone et récupère via la passerelle, avec un jeton de run temporaire ; le jeton Git n’y entre jamais.
  • Publication : push, PR/MR, fusion, suppression de branche passent par le broker après approbation de l’opération exacte (commit figé à la demande). Une approbation ne sert qu’une fois.
  • L’URL de clonage renvoyée par la forge doit désigner le même hôte que la connexion : un jeton n’est jamais présenté à un autre hôte.

Forges internes en HTTP

HTTPS est obligatoire. Une forge interne en HTTP (recette) n’est joignable que si l’administrateur liste hôte[:port] dans Forges Git → Réglages Git. Les jetons transitent alors en clair sur ce réseau : à réserver aux réseaux de confiance.
