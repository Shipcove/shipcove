Shipcove

Build in a safe cove. Ship with confidence.

A self-hostable platform where your teams hand development tasks to a coding agent. The agent, Pi, reads, changes and tests code in an isolated, ephemeral sandbox, pushes its branches and opens its pull requests on its own; every change is saved, and anything irreversible (default branch, merge, branch deletion) is approved by a human.

Quick start →Run the platform in minutes from the published images. User guide →Conversations, repositories, Git, plan, previews. Administration →Models, quotas, identity, Git forges, sandboxes and services. Security →Sandbox isolation, secrets, approvals, privacy.

What the platform does

  • One workspace per task: from a GitHub / GitLab repository (SaaS or self-hosted) or empty, with its own conversation, files and sandbox.
  • An autonomous agent: it runs commands, writes code, runs the tests, starts a PostgreSQL database or a Redis when needed, and shows you every action.
  • It shows its work: a task plan kept up to date for complex requests, screenshots taken automatically as soon as a web interface changes, an up-to-date git diff, and its deliverables (README, report, export…) offered as downloads.
  • Nothing irreversible without you: Pi pushes its branches and opens its pull requests on its own, but the default branch, merges and branch deletions wait for your approval, right in the conversation.
  • Nothing gets lost: a checkpoint is published to S3 after every write; a destroyed sandbox is restored exactly, and you can go back to the state before any message.
  • Your models, your rules: every call goes through LiteLLM (Anthropic, OpenAI, Azure, Bedrock, Mistral, local models…), with personal quotas.
  • Enterprise-ready: SSO (OIDC/Keycloak, SAML, LDAP/AD, GitHub, GitLab), MFA, secrets in Vault, audit, data retention.

How it works

  1. You write a request in a conversation, linked to a Git repository or not.
  2. The platform starts (or reuses) the conversation’s sandbox and restores its files and Pi’s state.
  3. Pi works: for a complex task it first sets out a plan; every tool call (command, read, write) is shown live; every write triggers a checkpoint.
  4. You follow the changed files in the Git tab (git diff, working branch), test the application through a preview, and approve in the conversation the Git publication Pi proposes.
  5. After a period of inactivity the sandbox is destroyed; everything is kept on S3 and resumes at the next message.
