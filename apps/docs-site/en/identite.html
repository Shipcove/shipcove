Identity and SSO

The platform has its own identity management; external providers are optional and managed in Administration → IAM & sign-in.

Local accounts and MFA

  • Passwords hashed with Argon2id, temporary lockout after failures, rate limiting per IP address.
  • TOTP two-factor authentication with recovery codes; policy: optional, required for administrators (default) or for everyone.
  • Open or closed sign-up, email verification, invitations, forgotten password.
  • Server-side sessions, revocable individually or globally.

Identity providers

Each provider is registered (disabled), tested then enabled. Secrets (client secret, bind password, SAML key) are written to Vault and never shown again. The console displays the callback URL to declare with the provider: https://<your-domain>/api/v1/auth/sso/<id>/callback.

OIDC / Keycloak

Confidential client, standard flow, PKCE S256.

{
  "issuer": "https://sso.example.com/realms/company",
  "clientId": "shipcove",
  "scopes": ["openid", "profile", "email"],
  "mfa": "auto"
}

SAML 2.0

Download the service provider metadata (link in the console) and import it into your provider; assertions must be signed. Prefer a persistent NameID.

{
  "entryPoint": "https://sso.example.com/realms/company/protocol/saml",
  "issuer": "shipcove",
  "idpCert": "MIIC…",
  "emailAttribute": "email",
  "nameAttribute": "displayName",
  "mfa": "auto"
}

LDAP / Active Directory

{
  "url": "ldaps://ldap.example.com",
  "bindDn": "cn=svc-coding,ou=services,dc=example,dc=com",
  "searchBase": "ou=people,dc=example,dc=com",
  "searchFilter": "(|(uid={{username}})(sAMAccountName={{username}}))",
  "usernameAttribute": "uid",
  "emailAttribute": "mail",
  "nameAttribute": "cn"
}

The service account only needs read access. The username entered is escaped in the filter; an empty password is refused (no anonymous bind).

GitHub and GitLab

For signing in to the platform: a dedicated OAuth application, optionally restricted to GitHub organizations or GitLab groups. (Connecting Git accounts to work on repositories is separate: see Git forges.)

MFA policy of providers

mfa valueEffect
autoLocal MFA applies, unless the provider attests MFA (OIDC amr/acr, SAML AuthnContextClassRef).
require_idpSign-in refused without MFA attested by the provider.
trust_idpThe provider enforces MFA itself.
localAlways the local policy (LDAP, GitHub, GitLab).

Account linking

  • An external identity is linked by the provider’s stable identifier, never by email address.
  • First sign-in: an account is created if automatic creation is enabled, unless the address already belongs to an account. The user then signs in with that account and links the identity in Settings → Security → Sign-in identities.
  • The last sign-in method of an account cannot be removed.
