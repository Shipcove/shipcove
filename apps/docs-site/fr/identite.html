Identité et SSO

La plateforme a sa propre gestion des identités ; les fournisseurs externes sont optionnels et se gèrent dans Administration → IAM & connexion.

Comptes locaux et MFA

  • Mots de passe hachés en Argon2id, verrouillage temporaire après échecs, limitation par adresse IP.
  • Double authentification TOTP avec codes de récupération ; politique : facultative, obligatoire pour les administrateurs (défaut) ou pour tous.
  • Inscriptions ouvertes ou fermées, vérification d’email, invitations, mot de passe oublié.
  • Sessions côté serveur, révocables individuellement ou globalement.

Fournisseurs d’identité

Chaque fournisseur s’enregistre (désactivé), se teste puis s’active. Les secrets (secret client, mot de passe de liaison, clé SAML) sont écrits dans Vault et jamais réaffichés. La console affiche l’URL de retour à déclarer chez le fournisseur : https://<votre-domaine>/api/v1/auth/sso/<id>/callback.

OIDC / Keycloak

Client confidentiel, flux standard, PKCE S256.

{
  "issuer": "https://sso.exemple.com/realms/entreprise",
  "clientId": "shipcove",
  "scopes": ["openid", "profile", "email"],
  "mfa": "auto"
}

SAML 2.0

Téléchargez les métadonnées du fournisseur de services (lien dans la console) et importez-les chez votre fournisseur ; les assertions doivent être signées. Préférez un NameID persistant.

{
  "entryPoint": "https://sso.exemple.com/realms/entreprise/protocol/saml",
  "issuer": "shipcove",
  "idpCert": "MIIC…",
  "emailAttribute": "email",
  "nameAttribute": "displayName",
  "mfa": "auto"
}

LDAP / Active Directory

{
  "url": "ldaps://ldap.exemple.com",
  "bindDn": "cn=svc-coding,ou=services,dc=exemple,dc=com",
  "searchBase": "ou=people,dc=exemple,dc=com",
  "searchFilter": "(|(uid={{username}})(sAMAccountName={{username}}))",
  "usernameAttribute": "uid",
  "emailAttribute": "mail",
  "nameAttribute": "cn"
}

Le compte de service n’a besoin que de la lecture. L’identifiant saisi est échappé dans le filtre ; un mot de passe vide est refusé (pas de liaison anonyme).

GitHub et GitLab

Pour la connexion à la plateforme : application OAuth dédiée, éventuellement limitée à des organisations GitHub ou des groupes GitLab. (Le rattachement de comptes Git pour travailler sur les dépôts est distinct : voir Forges Git.)

Politique MFA des fournisseurs

Valeur de mfaEffet
autoLa MFA locale s’applique, sauf si le fournisseur atteste une MFA (OIDC amr/acr, SAML AuthnContextClassRef).
require_idpConnexion refusée sans MFA attestée par le fournisseur.
trust_idpLe fournisseur impose lui-même la MFA.
localToujours la politique locale (LDAP, GitHub, GitLab).

Rattachement des comptes

  • Une identité externe est liée par l’identifiant stable du fournisseur, jamais par l’adresse email.
  • Première connexion : un compte est créé si la création automatique est activée, sauf si l’adresse appartient déjà à un compte. L’utilisateur se connecte alors avec ce compte et rattache l’identité dans Paramètres → Sécurité → Identités de connexion.
  • La dernière méthode de connexion d’un compte ne peut pas être retirée.
