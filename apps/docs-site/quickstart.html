Démarrage rapide

Lancez la plateforme sur une machine avec Docker, à partir des images publiées sur le registre GitHub, en une dizaine de minutes.

Prérequis

  • Linux (ou macOS avec Docker Desktop) avec Docker 24+ et Docker Compose v2 ;
  • git et openssl ;
  • au moins 4 cœurs, 8 Go de RAM et 30 Go de disque (davantage selon le nombre de sandboxes simultanées : 2 CPU / 4 Go chacune par défaut) ;
  • une clé d’API d’un fournisseur de modèles (Anthropic, OpenAI…) — ou le fournisseur factice pour un premier essai.

Installation

  1. Récupérer les fichiers de déploiement

    Le dépôt contient le fichier Compose, les scripts d’amorçage et la configuration de LiteLLM ; les applications elles-mêmes sont téléchargées sous forme d’images.

    git clone https://github.com/Shadow-p99/coding-platform.git
cd coding-platform/infrastructure/docker

  2. Configurer

    cp .env.example .env

    Dans .env, renseignez au minimum :

    # Images publiées sur ghcr.io
CAP_REGISTRY=ghcr.io/shadow-p99/
CAP_VERSION=0.1.0
CAP_SANDBOX_IMAGE=ghcr.io/shadow-p99/shipcove-sandbox:0.1.0

# Administrateur initial (créé au premier démarrage s'il n'en existe aucun)
CAP_ADMIN_EMAIL=admin@exemple.com
CAP_ADMIN_PASSWORD=un-mot-de-passe-long-et-unique

# Groupe propriétaire du socket Docker de l'hôte (valeur donnée par : stat -c %g /var/run/docker.sock)
CAP_DOCKER_GID=989

    Remplacez 0.1.0 par la dernière version publiée (voir les Packages du dépôt GitHub). Toutes les images d’une installation doivent porter la même version.

  3. Générer les secrets d’amorçage

    ./scripts/init-secrets.sh

    Le script crée .secrets/ (mots de passe PostgreSQL, clés Garage et LiteLLM, identifiants AppRole de Vault). Il est idempotent : relancé, il ne remplace rien. Ce répertoire n’est jamais versionné ; protégez-le et sauvegardez-le.

  4. Télécharger les images et démarrer

    docker compose pull
docker pull ghcr.io/shadow-p99/shipcove-sandbox:0.1.0
docker compose up -d

    Au premier démarrage, Vault est initialisé et déverrouillé, le stockage S3 (Garage) est configuré et les migrations de base de données sont appliquées. Vérifiez l’état :

    docker compose ps
curl -s http://localhost:8080/api/v1/health/ready

  5. Première connexion

    Ouvrez http://localhost:8080 et connectez-vous avec CAP_ADMIN_EMAIL / CAP_ADMIN_PASSWORD. Les administrateurs doivent activer la double authentification (TOTP) dès la première connexion : scannez le QR code avec votre application d’authentification et conservez les codes de récupération.

  6. Brancher LiteLLM et activer un modèle

    Les modèles se déclarent dans LiteLLM (son interface http://localhost:4000/ui avec la clé maître de .secrets/litellm_master_key, son API ou son config.yaml) ; la plateforme les découvre.

    • Administration → Modèles (LiteLLM), carte Connexion à LiteLLM : gardez le LiteLLM fourni, ou indiquez l’URL et la clé d’administration d’un proxy LiteLLM existant (Tester, puis Enregistrer) ;
    • Recharger les modèles : les modèles de LiteLLM apparaissent, désactivés, avec des coefficients préremplis depuis leurs prix connus (1 crédit = 0,001 $) ;
    • activez-en un, choisissez-le par défaut, puis Tester envoie une requête réelle. Une liste blanche d’utilisateurs peut restreindre l’accès à un modèle (vide = tout le monde).

  7. Inviter des utilisateurs et démarrer une conversation

    • Administration → Invitations : invitez vos collègues par email (nécessite un serveur SMTP : Administration → Notifications & SMTP), ou créez leurs comptes dans Utilisateurs ;
    • sur la page d’accueil, écrivez votre première demande à Pi ; choisissez éventuellement un dépôt sous la zone de saisie (après avoir configuré une forge Git et rattaché votre compte).

Essayer sans fournisseur de modèles

Le profil dev ajoute un fournisseur LLM factice (scénarisable, pour la recette) et Mailpit, qui capture les emails :

docker compose --profile dev up -d

Déclarez alors le modèle openai/mock-model avec le paramètre api_base = http://mock-llm:4010/v1 et une clé quelconque. Les emails sont visibles sur http://localhost:8025 (configurez le SMTP mailpit:1025 dans l’administration).

Le profil dev n’est pas destiné à la production.

Mettre à jour

# dans .env : CAP_VERSION et CAP_SANDBOX_IMAGE vers la nouvelle version
git pull
docker compose pull
docker pull ghcr.io/shadow-p99/shipcove-sandbox:<version>
docker compose up -d

Les migrations sont appliquées automatiquement par le service migrate avant le démarrage des API. Les sandboxes en cours conservent leur image jusqu’à leur prochain redémarrage.

Et ensuite ?

  • Installation et configuration : URL publique, TLS, previews, ports, répliques ;
  • Identité et SSO pour connecter votre annuaire ;
  • Forges Git pour travailler sur vos dépôts ;
  • Exploitation avant une mise en production.
