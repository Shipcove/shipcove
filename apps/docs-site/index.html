Shipcove

Build in a safe cove. Ship with confidence.

Une plateforme auto-hébergeable où vos équipes confient des tâches de développement à un agent de code. L’agent Pi lit, modifie et teste le code dans une sandbox éphémère et isolée, pousse ses branches et ouvre ses pull requests en autonomie ; chaque modification est sauvegardée, et ce qui est irréversible (branche principale, fusion, suppression) est approuvé par un humain.

Démarrage rapide →Lancer la plateforme en quelques minutes à partir des images publiées. Guide utilisateur →Workspaces, conversation, modifications, Git, previews. Administration →Modèles, quotas, identité, forges Git, sandboxes et services. Sécurité →Isolation des sandboxes, secrets, approbations, confidentialité.

Ce que fait la plateforme

  • Un workspace par tâche : depuis un dépôt GitHub / GitLab (SaaS ou auto-hébergé) ou vierge, avec sa conversation, ses fichiers et sa sandbox.
  • Un agent autonome : il exécute des commandes, écrit du code, lance les tests, démarre au besoin une base PostgreSQL ou un Redis, et vous montre chaque action.
  • Rien ne se perd : un checkpoint est publié sur S3 après chaque écriture ; une sandbox détruite est restaurée à l’identique, et vous pouvez revenir à l’état d’avant n’importe quel message.
  • Rien ne part sans vous : push, pull/merge requests et fusions ne sont exécutés qu’après votre approbation de l’opération exacte.
  • Vos modèles, vos règles : tous les appels passent par LiteLLM (Anthropic, OpenAI, Azure, Bedrock, Mistral, modèles locaux…), avec quotas personnels.
  • Prête pour l’entreprise : SSO (OIDC/Keycloak, SAML, LDAP/AD, GitHub, GitLab), MFA, secrets dans Vault, audit, rétention des données.

Comment ça marche

  1. Vous écrivez une demande dans la conversation d’un workspace.
  2. La plateforme démarre (ou réutilise) la sandbox du workspace, restaure ses fichiers et l’état de Pi.
  3. Pi travaille : chaque appel d’outil (commande, lecture, écriture) s’affiche en direct ; chaque écriture déclenche un checkpoint.
  4. Vous suivez les fichiers modifiés dans le panneau Modifications (diff de type Git), testez l’application via une preview, et approuvez la publication Git proposée par Pi.
  5. Après une période d’inactivité, la sandbox est détruite ; tout est conservé sur S3 et repart au message suivant.
